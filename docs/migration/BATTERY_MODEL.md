# Battery model — P4.7a

Port of `src/argusnet/planning/battery.py` into `rust/argusnet-planning`.

## What was ported, and what was not

Scope was set by reachability, not by the module's surface area. The methods
reachable from outside `battery.py` are:

| Symbol | External call sites | Ported |
|---|---|---|
| `return_home_cost_wh` | 7 | yes |
| `dynamic_reserve_wh` | 5 | yes |
| `segment_cost_wh` | 1 | yes |
| `travel_cost_wh` | 0 direct — via `segment_cost_wh` | yes |
| `climb_cost_wh` | 0 direct — via `segment_cost_wh`, `return_home_cost_wh` | yes |
| `BatteryState.consume` | yes | yes |
| `route_cost_wh` | 0 | no |
| `usable_capacity_wh` | 0 | no |
| `compute_route_budget` | 0 | no |
| `insert_return_waypoint` | 0 | no |
| `BudgetResult` | 0 | no |
| `BatteryState.fraction` | 0 | no — see below |

`BatteryState.fraction` is a property named for a fraction that returns
**watt-hours**; its own comment says "caller normalises against capacity", and
`sim.py` does exactly that by hand. It is referenced nowhere in `src/` or
`tests/`. Carrying the name across would give a misleading identifier a second
life in a typed language, where `fraction()` returning an energy is worse than
it is in Python. The port provides `BatteryState::fraction_of(capacity_wh)`
instead, which computes what `sim.py` computes.

## Behaviours reproduced deliberately, not tidied

Three of the reference's quirks are load-bearing for parity and are reproduced
with a comment saying so, because each looks like a defect:

- **`climb_cost_wh` branches on `delta_z_m > 0`**, so a delta of exactly zero
  takes the *descent* power. This costs nothing either way (the duration is
  zero), which makes the operator unobservable — see the equivalent mutant
  below.
- **`BatteryState::consume` carries the timestamp through unchanged.** A state
  that spends energy but never advances its own clock reads like an oversight,
  but nothing consumes the field, so "fixing" it here would be an unverifiable
  behaviour change inside a port.
- **Neither a negative distance nor a negative cost is guarded against.**
  `travel_cost_wh(-50.0)` returns a negative energy and `consume(-3.0)` adds
  energy back. Both are in the fixture so the port cannot quietly add a guard.

The speed floors (`max(speed, 0.01)`) are floors rather than guards: a zero
cruise speed yields an enormous but finite cost, not an infinity.

The static reserve in `dynamic_reserve_wh` is a **floor** on the dynamic
estimate. A port that took the dynamic value alone would let a platform far
from home hold back less than its configured minimum — the failure would only
show up on the platforms furthest from home, which is the worst place for it.

## Fixture

`tests/fixtures/battery_costs.json`, generated by
`scripts/capture_battery_fixture.py`. The generator **calls the reference and
reads its results back**; it does not recompute the formulas. A generator that
recomputed them would agree with a port that shared its author's misreading
while both disagreed with Python.

Parity is asserted **bit-exactly** (`assert_eq!` on `to_bits()`). These are
closed-form scalar expressions with no summation order to differ on, so a
tolerance would only hide a wrong constant. Floats cross the boundary as
strings because `serde_json`'s parser is one ULP off `str::parse::<f64>` on
some literals — the same trap that broke the sensor error model's exact
comparison in P4.5a.

Cases: 5 travel, 6 climb, 5 segment, 60 return-home (2 models × 5 geometries ×
6 winds, each also covering `dynamic_reserve_wh`), 5 consume.

Four coverage tests assert the fixture actually reaches the branches it claims
to, so a port that collapsed a branch nothing exercises could not pass: both
sides of the climb/descent split, both sides of the static-reserve floor, the
groundspeed floor, and a wind track below the `1e-6` guard.

## Mutation testing

18 mutations, each verified to have reached disk before the tests ran — a patch
that silently misses its target produces a clean run that reads as a survivor,
which has happened twice in this migration. **17 caught by a named test; 1
survivor, proven equivalent.**

Two survivors from the first pass were genuine test gaps, and both came from
the same mistake: a test that proves a behaviour *exists* without pinning
*where* it is.

- **The groundspeed floor's value was unpinned.** `wind_moves_the_return_cost_in_the_expected_direction`
  asserted that two enormous headwinds cost the same, which proves a floor
  exists but holds for any floor value. Changing `0.25 * cruise` to `0.01`
  passed. The fixture could not catch it either: its strongest wind was a
  *tailwind* against the homeward track, so no case ever reached the floor.
  Closed by adding a headwind past the floor to the fixture, and by
  `the_groundspeed_floor_sits_at_a_quarter_of_cruise`, which flies a level leg
  — so the whole cost is the travel term — and asserts the floored cost is
  exactly four times still air. Exactly, not approximately: scaling a quotient
  by four is a power-of-two exponent bump that cannot disturb the mantissa.
- **The wind guard's threshold was unpinned.** `wind_is_ignored_when_there_is_no_horizontal_track`
  used a position with a horizontal distance of exactly zero, which `> 1e-6`
  and `> 0.0` reject identically. Closed with a track of `5e-7` — short of the
  guard but genuinely non-zero — in both the fixture and
  `the_wind_guard_ignores_a_track_shorter_than_a_micron`.

### The equivalent mutant

Flipping `delta_z_m > 0.0` to `>= 0.0` in `climb_cost_wh` is caught by nothing,
and no test *can* catch it:

- for any `delta_z_m != 0` the two comparisons agree, selecting the same power;
- at `delta_z_m == 0` — and at `-0.0`, where the operators do disagree — the
  duration is `0.0.abs() / speed == 0.0`, and `power * 0.0 / 3600.0` is `+0.0`
  for every finite power, so the selection is unobservable, down to the sign
  bit;
- `NaN` fails both comparisons identically.

`the_climb_comparison_operator_is_unobservable_at_a_zero_delta` states that
proof as executable assertions. Adding a test that "caught" this mutation would
mean asserting which power a zero delta picks — something the reference does
not expose either — so it is recorded as equivalent rather than tested around.
