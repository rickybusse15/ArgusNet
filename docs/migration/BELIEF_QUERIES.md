# Belief queries (P4.6c)

`src/argusnet/mapping/belief.py` → `rust/argusnet-mapping/src/belief.rs`.

`WorldBeliefQuery` is the read-only facade planners use: coverage, confidence,
heights, obstacles, geofence membership, frontier ranking and corridor safety,
without touching raw arrays or simulation truth. It is the half of P4.6 that
P4.8 needs and that P2.1b in the graphics lane has been waiting on.

`tests/fixtures/belief.json`, regenerated by
`scripts/capture_belief_fixture.py`: 20 scenarios, 431 cells, 32 corridor
probes. Every scenario compares the **whole cell table** — every cell, all
twelve fields — plus the frontier list, the per-cell expected gain, every
ranking and every corridor answer.

That is not thoroughness for its own sake. The divergences this module is prone
to are not wrong numbers, they are **wrong cells**: one cell of a ragged grid
reporting itself outside the geofence, or one edge patch divided by the wrong
denominator. Neither shows up in a scalar probe or an aggregate.

## Two coordinate systems that do not agree, deliberately

`GridBounds` sizes the grid as `ceil(span / resolution)`, so when the span is
not a whole number of cells **the grid extends past the bounds**. The
reference's predicates split on that gap rather than papering over it:

- `coverage_at`, and everything built on it, tests the raw inclusive bounds
  first and returns `0` outside them.
- `height_estimate_at` does **not** test the bounds. It clamps and reports the
  last cell's height.

The consequence looks like a bug and is reproduced: `cell_ij` on the **last**
cell of a ragged grid takes its centre from `ij_to_xy`, which can land past
`x_max_m`, so the cell reports itself `outside_geofence` with zero coverage
while the grid holds counts for it. The `ragged_grid_last_cell_outside`
scenario has 28 such cells and the capture script refuses to write a fixture
without at least one.

## The expected-gain denominator shrinks at the edges

`expected_coverage_gain` divides by the **patch** size, which is 4 at a corner,
6 along a side and 9 inside — the low edge is clamped with `max(0, i - 1)` and
the high edge by numpy's own slicing. A port that always divided by 9 agrees on
every interior cell and is wrong on the whole border. 125 fixture entries
distinguish the two.

## `safe_corridor_between` walks numpy's `linspace`, exactly

`np.linspace(0, 1, n)` is `k * (1 / (n - 1))` with the final value forced to
exactly `1.0`. Two plausible simplifications are both wrong, and both needed a
corridor **solved for** rather than stumbled on, because the difference between
the spellings is about one ULP and only matters within one ULP of a cell
boundary:

| Wrong spelling | Fixture case | How it was found |
|---|---|---|
| `k / (n - 1)` | `linspace_sample_positions`, n = 7 | Sample k = 5 lands in cell 7 under numpy and cell 8 under the naive form; every other sample agrees. Cell 7 is left uncovered, so the answers differ. |
| drop the forced final `1.0` | `endpoint_snap`, n = 50 | `49 * (1/49) != 1.0`, so the last sample ends at `7.999999999999999` instead of `8.0`. The segment ends exactly on the 7\|8 boundary; only k = 49 differs. |

**n = 16, the reference's default, cannot separate any of this** — the two
alpha sequences agree there. A fixture built only at the default would pass a
port with either wrong spelling.

## A guard that checked the wrong property, twice

The first version of the discrimination guard asserted that a **sample count
where the alpha sequences differ** was present in the fixture. It passed — and
the `corridor/naive-linspace` mutant survived the entire mutation set anyway,
because a divergent sample count is not the same as a divergent *answer*. The
samples have to land in cells that actually differ in safety.

The guard now records, per corridor probe, the answer each wrong spelling would
give, and refuses to write the fixture unless at least one probe **flips**. The
parity test asserts the same property from the Rust side, so the set cannot
silently lose its teeth later.

This is the second time in this migration that a guard checked "do the numbers
look interesting" instead of "does the wrong implementation fail" — the
formation-offset guard in P4.7h made the same mistake. The rule that works:
**implement the wrong version and require it to disagree.**

## What the cell table cannot reach

A cell is always evaluated at its own centre, which is never below `x_min_m`
and never outside the grid. So the cell table can never exercise `xy_to_ij`'s
lower clamp or either inclusive bound test. The fixture therefore also carries
**scalar probes** at chosen points — exactly on each bound, one ULP inside, one
ULP outside, and far below the origin — with all nine scalar queries recorded.
Three mutants die only here.

## Mutation result: 63 of 66 caught, 3 proven equivalent

The first pass caught **53 of 66**. The 10 that were closed needed real fixture
work, not more cases of the same shape:

- the two linspace spellings above;
- the inclusive bound tests and the lower clamp, which needed scalar probes;
- `is_known_safe` dropping its observation test, which needed an **unobserved**
  cell with a *low* obstacle probability. With `p >= 0.4` the obstacle test
  fails anyway and dropping the observation test is invisible;
- the sample-count floor, which needed a corridor whose start is unsafe and
  whose end is safe — at `n = 1` the single sample is the *endpoint*;
- `confidence_at`'s `max(0.0)` floor, pinned as a **unit test** rather than in
  the fixture: the reference's occupancy is a sigmoid so `1 - risk` is always
  positive and the floor never fires, but the Rust API takes the probabilities
  as data and a caller can hand it something outside `[0, 1]`.

The three survivors are equivalent, each checked against the fixture rather
than argued from the source alone:

| Mutant | Why it cannot differ | Checked |
|---|---|---|
| `gain/no-size-floor` (`size.max(1)` → `size`) | `(i, j)` is always in its own patch, so the ranges are never empty | 0 patches of size 0 across 431 cells |
| `score/risk-drops-fence-penalty` | `frontier_cells` already skips cells outside the geofence, so the penalty arm is dead — in the reference too | 0 of 62 scored candidates are outside the geofence |
| `score/no-ij-tiebreak` | `frontier_cells` emits cells ij-ascending and both sorts are stable, so ties already keep that order | 0 of 20 scenarios have a non-ascending frontier list |

The last two are kept rather than simplified away: the tie-break is the only
thing keeping the ranking well-defined if `frontier_cells` ever stops being
ordered, and the dead penalty arm is dead in the reference, so removing it here
would make the two read differently for no gain.

## Not in this slice

P4.6 also asks for **immutable belief revisions and dirty tile patches** for
planners and the renderer. Those are a publishing layer over this query
surface, not part of it, and they want the shape the runtime actually emits to
drive them rather than a guess from the schema — the same reasoning that
deferred P2.1b. This slice ports the query surface `belief.py` defines; the
patch stream is the next one.

`OccupancyGrid`'s own log-odds update model is also not ported. The fixture
reads probabilities back out of the real Python grid and hands those exact
floats to Rust, so the query surface is pinned without a second thing under
test. The update model belongs with the rest of the mapping state.
