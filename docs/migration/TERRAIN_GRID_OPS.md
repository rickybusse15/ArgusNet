# Terrain grid operations (P4.3b)

`src/argusnet/world/procedural.py` → `rust/argusnet-world/src/grid_ops.rs`.

Four functions that sit directly on the P4.3a noise primitives and feed every
mask the terrain builders use: `_slope_grid`, `_dilate_mask`, `_smooth_heights`
and `_ellipse_mask`.

`tests/fixtures/grid_ops.json`, regenerated by
`scripts/capture_grid_ops_fixture.py`: 8 slope cases, 6 dilations, 9 smoothing
runs and 6 ellipse masks. **Whole grids are compared bit-for-bit, not sampled.**
The divergences these functions are prone to are edge-handling divergences —
they appear on the border and nowhere else, so a fixture that probed interior
cells would pass a port that got every boundary wrong.

## `np.gradient` is central inside and one-sided at the edges

With numpy's default `edge_order=1`:

```text
interior: (f[i+1] - f[i-1]) / (2 * h)
first:    (f[1]   - f[0])   /  h
last:     (f[n-1] - f[n-2]) /  h
```

The interior divisor is `2.0 * h` formed once. The plausible wrong port clamps
the index instead — reading `f[0]` twice at the border — which yields **half**
the correct derivative there and is right everywhere else. The guard implements
exactly that and requires it to disagree; 7 of the 8 slope cases catch it.

An axis shorter than two samples makes numpy raise, so the port returns an
error rather than inventing a derivative.

## Two naming traps, one harmless and one not

`_slope_grid` unpacks `dz_dy, dz_dx = np.gradient(...)`, naming the **axis-0**
derivative `dz_dy` — the opposite of the `[i, j] = [x, y]` convention the rest
of the crate uses. It does not matter here, because both derivatives are
immediately squared and summed. Recorded so nobody "fixes" it and then wonders
why nothing changed, and so nobody assumes the same naming holds where it
*would* matter.

`_smooth_heights`'s kernel is `(4*centre + up + down + left + right) / 8` — a
weight sum of **8 over 5 cells**, which is *not* an average. That one does
matter, and it is easy to read as a mean and "simplify" to `/ 5`.

**On a constant field the two are identical.** A constant-field test case
proves nothing about the weighting, so every smoothing case in the fixture uses
a field with structure, and the guard recomputes each one with a true five-cell
mean and requires a disagreement.

Edges are padded by **replication** (`mode="edge"`), so a border cell sees
itself as its missing neighbour.

## Mutation: 37 of 38 caught, 1 proven equivalent

The first pass caught **36**. Two survivors:

**`ellipse/ry-floor` was a real gap, and the cause is worth naming.** The
sub-metre ellipse case held `ys = [0.0]`, so `dy` was `0` whatever the
y-radius was, and the y-radius floor was invisible while the x one was tested.
Holding an axis constant makes that axis's parameter untestable — the same
shape of mistake as measuring an intermediate instead of an output. Both axes
now vary, there is a case with a sub-metre radius on **one** axis only so the
two floors cannot be confused, and the guard requires *each* floor to change an
answer (it now reports `rx: 3, ry: 6`).

**`grad/first-edge-reversed` is a proven equivalent.** Reversing a one-sided
edge difference flips its sign, and the sign is not observable through
`slope_grid` — the only caller — because the derivatives are immediately
squared and `(-a) * (-a)` is bit-identical to `a * a`. Checked over 200,000
random pairs: zero disagreements. The magnitude and the divisor *are*
observable and both are pinned.

## Also pinned

- Dilation is **eight-connected** and padded with `false`, so it never wraps or
  bleeds in from outside; a corner seed reaches only four cells. A non-positive
  iteration count returns the mask unchanged rather than dilating once.
- Each dilation pass reads the **previous** pass's output, so N passes grow N
  rings — a port that re-read the original mask every pass grows one ring
  whatever N is.
- `_smooth_heights` double-buffers, and its `passes` and `blend` degenerate
  cases (zero, negative, and a blend above 1 that extrapolates rather than
  interpolating — the reference does not guard it and neither does the port).
- `_ellipse_mask` includes its boundary (`<= 1.0`); the fixture places 8
  samples exactly on it, without which `<=` and `<` are indistinguishable.
