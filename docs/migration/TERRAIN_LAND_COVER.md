# Terrain land cover (P4.3d)

`src/argusnet/world/procedural.py` → `rust/argusnet-world/src/land_cover_build.rs`.

Fourth slice of P4.3: `_sample_mask_to_grid` and the classification half of
`build_land_cover_layer` — the pass that turns heights, slopes and the P4.3c
semantic masks into a class and density raster.

`tests/fixtures/land_cover.json`, regenerated by
`scripts/capture_land_cover_fixture.py`: **19 scenes**, whole grids compared
bit-for-bit. The fixture drives the real `build_land_cover_layer` with
`obstacles=()` and `patches=()`, so the trailing polygon loops are no-ops and
the layer it returns *is* this pass's output.

## This grid is the transpose of everything else in the crate

`build_land_cover_layer` builds its coordinates with
`np.meshgrid(x_values, y_values)` and **no `indexing="ij"`**, so numpy's default
applies and **axis 0 is y**. `grid_ops::Grid` and `semantic::semantic_masks` are
documented `(i = x, j = y)`. The two conventions sit forty lines apart in the
same reference file.

Getting it wrong produces a land-cover map that is plausible, self-consistent
and rotated — the same class of bug as the ellipse in P4.3c, which cost 0.013 m
on the lake preset.

Two things guard it. `CoverGrid` is spelled `rows`/`cols`, never `nx`/`ny`. And
the source masks arrive as a **`CoverMask`**, a type that exists only to make
the reinterpretation explicit: `CoverMask::from_axis0_y` is the one place the
axis names change, instead of an unstated assumption inside a function body.
Every scene uses a **non-square** grid, so a transposed port cannot even produce
the right shape, and all 19 cases distinguish the two layouts.

## `np.rint` is banker's rounding — the third time

`_sample_mask_to_grid` resamples with `np.rint`, which rounds **ties to even**.
Rust's `f64::round()` is half-away-from-zero. The route-cache key (P4.7d) and
the POI priority boost (P4.7f) were the first two.

None of the substantive scenes produce a tie: their cell centres never land on
a half-integer source index. Scanning bounds against terrain and cover
resolutions found **212 combinations** that do, on both axes, and one of them is
in the fixture at 8 m into 24 m so the resampler is doing a real 3:1 downsample
rather than an identity map. *Not found by sampling is not unreachable* — the
same lesson as the bit-exact slope thresholds in P4.3c.

## The order of the seven assignments is the contract

Water, wetland, snow, rocky, forest, scrub, road — each overwriting the last.
The masks are **not mutually exclusive**: `snow_mask` excludes only water, so
snow lands on top of wetland wherever both hold. Reordering the blocks changes
the map while leaving every individual predicate correct.

Density follows **two different rules in the same function**. Wetland, snow,
rocky and road *assign*; forest and scrub take `max(existing, new)`. Road
assigns **zero** — the only rule in the pass that lowers a density, so a road
over forest clears the foliage rather than keeping the larger value.

## Three clamps that no preset can reach

| Clamp | Range | Reachable from the preset table? |
|---|---|---|
| second water level | `[0.03, 0.30]` | **no** — the only four presets that reach the code have water_bias 0.08, 0.16, 0.2 and 0.28, all interior to both this and `_semantic_masks`' `[0.01, 0.35]` |
| forest moisture floor | `max(0.35, …)` | **no** — it binds above vegetation_bias 1.1111, and the table's highest is jungle_canopy's 0.95 |
| snow bias comparison | `> profile.snow_bias` | **no** — `>` versus `>=` needs elev_norm exactly on the bias, and the lowest in the table is 0.2 |

The port takes the profile as **data**, so the fixture drives these directly
through per-scene profile overrides rather than declaring them equivalent. A
future preset edit that moved a bias would otherwise silently break an
untested clamp.

## Mutation: 56 of 60, after a first pass at 45

Four survivors, each proven equivalent below.

The first pass caught **45**, and closing the gap was mostly a matter of
searching for a scene on the **final classification** rather than on a property
that looked like it should matter. Three times a search on a proxy found
plenty of candidates on scenes where the mutant still survived:

| Survivor | Proxy searched | Why it found nothing usable |
|---|---|---|
| `wetland/valley-dropped` | valley cells outside lowland | of 109 in `river_valley`, 9 clear the water and slope gates, and **all 9 become road** — the rule that runs last |
| `wetland/moisture-threshold` | cells with moisture in `[0.60, 0.68]` | plenty; every one was overwritten by a later rule |
| `forest/moisture-floor` | cells inside the window the floor opens | they failed the *other* forest tests — elevation and slope |

Each was closed by searching the classification itself. For the valley term
that meant 63 qualifying scenes and one usable cell on an 8×12 grid; a first
search over six presets found zero, which was **not evidence of an equivalence,
only an incomplete search** — it had omitted `mountain_pass`.

**Coverage is a property of the geometry, not the case count.** Moving the
default bounds origin off `(0, 0)` — needed so a port that reads
`source_x_min_m` where it means `source_y_min_m` cannot hide — changed the
terrain and cost four mutants their discrimination at once, including two that
had been caught. The capture script's guard caught that on the very next run,
which is why it runs on every capture rather than once.

### The four survivors

**`moisture/not-clamped` is proven equivalent.** `moisture` is only ever
compared against `0.68` (wetland), `0.42` (scrub) and the forest threshold,
which is `max(0.35, 0.55 - veg * 0.18)` and so lies in `[0.35, 0.55]`. All three
are strictly inside `(0, 1)`, so clamping a value that was already above 1 or
below 0 cannot move it across any of them. The clamp is defensive, not
load-bearing.

**The two scale floors are proven equivalent.** `max(cols - 1, 1)` differs from
`cols - 1` only for a one-column source, where the only valid index is 0 and
`clamp(_, 0.0, 0.0)` returns 0 for every input — including the `NaN` that
`inf * 0.0` produces, which `as usize` saturates to 0. The test computes both
spellings over nine ratios including the infinities and NaN and requires them to
agree.

**The extent floor is `unreachable`, not equivalent**, and the distinction is
kept. `max(width, 1e-9)` would genuinely change the answer for an extent
strictly between 0 and a nanometre; `Bounds2D` rejects a non-positive extent and
the terrain layers here are hundreds of metres across, so no caller can build
one. At exactly zero the two agree, because the clamp absorbs the resulting
infinity.

## Boundaries the fixture cannot reach

The fixture drives the reference, so it can only use inputs the terrain
generator actually produces. Nine unit tests cover what it cannot:

- `heights <= ground_plane + 1.0` and `heights <= water_level` **include** their
  boundaries; `slopes > 0.52` and `elev_norm > snow_bias` **exclude** theirs.
  Four boundary tests, because both spellings appear in the same function.
- `max(h_max - h_min, 1.0)` — a search over ten scene geometries found **no
  preset producing under a metre of relief**, so the elevation-span floor can
  only be reached by handing the function a flat field directly.
- `np.uint8` **truncates**: `190 × 0.15 = 28.5` becomes 28, not 29. Winter is
  the only season whose scaling is fractional, so no summer or autumn case can
  tell truncation from rounding.

Two of those tests started out asserting nothing. "A 1×1 source answers true
everywhere" is true of the right version *and* the wrong one; a property that
holds either way is not an assertion. They now run both spellings and require
agreement.

## Not in this slice

The **obstacle and patch polygon overlay** at the end of
`build_land_cover_layer` — `ForestStand` and `PolygonPrism` footprints rasterised
with `_point_in_polygon` — is P4.3e, together with `procedural_terrain_grid`.
That grid is the **only function in this file that uses numpy's RNG** (14 uses),
so under ADR-006 it is compared on statistical envelopes rather than bit
patterns, and it is the reason P4.3e is a different kind of slice from a–d.
