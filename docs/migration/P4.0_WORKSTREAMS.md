# P4.0 — parallel workstreams

> Scope: this document records compatibility-port behavior and its dated evidence.
> The final [independently scheduled Rust runtime](../RUST_RUNTIME_ARCHITECTURE.md)
> is delivered separately by P4.10 in [the delivery plan](DELIVERY_PLAN.md).
> Do not reinterpret stage-fixture results as full runtime or hardware acceptance.

P4.0 ("complete shared types and adapters") splits into two streams that touch
disjoint files and can run at the same time. This document is the contract
between them: what each owns, what neither may do, and how they land.

Read [`DELIVERY_PLAN.md`](DELIVERY_PLAN.md) §P4.0 for the goal, and
[`FIELD_PARITY.md`](FIELD_PARITY.md) for the wire-field dispositions the work
has to honour.

---

## Why the split is safe

Verified before writing this, not assumed:

- `rust/argusnet-viewer/src/replay.rs` defines **23 public DTO types** that no
  other crate imports.
- Its only Bevy usage is `Resource` (2 occurrences) and `Vec3` (14). No
  `Component`, no `Entity`, no rendering types.
- Its only cross-crate reference is `use argusnet_proto::pb` inside
  `mod live_stream`, already behind `#[cfg(feature = "live-stream")]`.
- Nothing in `argusnet-types`, `argusnet-proto`, `argusnet-core` or
  `argusnet-server` refers to those DTOs.

So the replay DTOs and the runtime/wire types are two separate bodies of code
that happen to describe similar things. They can be worked on independently.

## Stream A — extract `argusnet-replay` (assigned to Codex)

**Goal.** Move the replay DTOs and their normalizers out of the viewer into a
new `argusnet-replay` crate, free of Bevy and prost, per P4.0's "keep runtime
types free of Bevy/prost".

**Files owned.** Stream A is the only stream that may edit these:

```
rust/argusnet-replay/**            (new crate)
rust/argusnet-viewer/src/replay.rs
rust/argusnet-viewer/Cargo.toml
Cargo.toml                         (workspace members list only)
```

**What to do.**

1. Create `rust/argusnet-replay` with `serde`, `serde_json` and `glam`.
   Not `bevy`. Not `prost`/`tonic` outside the optional feature below.
2. Move the 23 DTO types and their `Deserialize` impls, custom visitors and
   normalizers across unchanged in behaviour.
3. Replace `bevy::prelude::Vec3` with `glam::Vec3`. **These are the same type** —
   `bevy_math` re-exports `glam` — so this is a rename at the import, not a
   conversion, **provided the versions stay unified**. Checked against
   `Cargo.lock` at the time of writing: exactly one `glam` (0.32.1) for
   `bevy_math` 0.19.1, so `glam = "0.32"` in the new crate resolves to the same
   type Bevy uses. Re-check this if Bevy is bumped — two glam versions in the
   lockfile would make `Vec3` two incompatible types, and the symptom is a type
   error at the viewer boundary, not a silent miscompile. Treat that as a
   blocker to raise, not to paper over with a conversion shim.
4. The two `Resource` derives do **not** move. `Resource` is a `bevy_ecs`
   derive and belongs to the viewer. Either wrap the moved type in a viewer-side
   newtype that derives `Resource`, or put the derive behind an optional
   `bevy` feature on the new crate. Prefer the newtype: it keeps the new crate
   Bevy-free unconditionally, which is what P4.0 asks for.
5. Keep `mod live_stream` gated on `live-stream` as it is today, with
   `argusnet-proto` an optional dependency of the new crate.
6. Re-export from `argusnet-viewer::replay` so the rest of the viewer compiles
   unchanged. The viewer's own tests should keep passing without edits — if they
   need edits, the move changed behaviour and that needs explaining.

**Done when.** `cargo test --workspace` green, `cargo clippy --workspace
--all-targets -- -D warnings` clean, the headless render smoke still passes,
and `rust/argusnet-replay` has no `bevy` in its dependency tree
(`cargo tree -p argusnet-replay | grep bevy` returns nothing).

**Note on history.** An earlier slice ("B4") proposed almost exactly this
extraction to speed up builds, and it was **retired** because the measurements
did not support that rationale — the viewer already tested in 9–12 s. This
stream is not that argument revived. The justification here is architectural:
P4.0 requires DTOs free of Bevy so they can be shared without dragging a
renderer in. If a build-time improvement falls out, it is a side effect, not
the case for doing it.

## Stream B — complete `argusnet-types`, consolidate `argusnet-proto` (assigned to Claude)

**Goal.** One semantic runtime type definition, with the wire conversions
consolidated and the gaps G0 found actually closed.

**Files owned.** Stream B is the only stream that may edit these:

```
rust/argusnet-types/src/lib.rs
rust/argusnet-core/src/lib.rs      (PlatformFrame and its construction)
rust/argusnet-proto/src/lib.rs
rust/argusnet-proto/tests/roundtrip.rs
rust/argusnet-server/src/lib.rs
rust/argusnet-server/tests/grpc_parity.rs
docs/migration/FIELD_PARITY.md
```

**What to do**, in order — each item is a finding from G0 with a test already
pinning today's behaviour, so each starts by making that test fail:

1. ~~**Give `PlatformFrame` real `target_metadata` and `safety_events` fields.**~~
   **Done — PR #54.** The server's graft is deleted and the pinning test, now
   `target_metadata_and_safety_events_reach_ingest_and_latest_frame_alike`,
   asserts the opposite of what it did.
2. **Resolve `mode_probability_cv`'s unset encoding.** `track_to_pb` sends
   `unwrap_or(1.0)`; `track_from_pb` treats only `0.0` as `None`, so `None`
   returns as `Some(1.0)`. Pinned by
   `mode_probability_cv_none_does_not_survive_the_wire`. The proto may not be
   renumbered or reinterpreted, so the fix has to work within the existing
   `double` — likely a companion presence field or an agreed sentinel,
   documented either way.
3. **Consolidate the `_to_pb` / `_to_pb_ref` duplication.** Two nearly
   identical bodies per type is the "share field policy instead of doubling it"
   the plan names. Preserve the ownership behaviour: move owned values, borrow
   or clone only where the caller actually needs it.
4. **Extend the round trips** to the remaining conversions and to the cases
   P4.0 calls out explicitly: all optional payloads present and absent, and
   invalid covariance lengths.
5. **Update `FIELD_PARITY.md`** as dispositions change. Rows that become
   `carried` must be backed by a round trip, not by inspection.

## Rules both streams follow

- **No proto changes.** P4.0 says no field is removed, renumbered or
  reinterpreted. Both streams work within `world_model.proto` as it stands. A
  change that seems to need one is a conversation, not a commit.
- **Base on `main`, never on each other's branch.** Two PRs in this repo were
  merged into a stacked base rather than into `main` and their content never
  reached it; the recovery was PR #51. Each stream opens its own PR against
  `main` and merges independently.
- **Stay inside your file list.** If a change needs a file the other stream
  owns, stop and say so rather than reaching across.
- **The Python replay fixtures must stay green.** They are the cross-language
  contract, and `python3 -m pytest tests/ -q` is the check.

## Status — P4.0 complete (2026-09-09)

Both streams have landed. This document is kept as the record of how the split
was drawn and what it cost, not as live work.

| stream | landed as |
|---|---|
| A — extract `argusnet-replay` | #58 |
| B — complete types, consolidate proto | #54 (item 1), #57 (items 2-5) |

### Both streams were done by Claude, and that was a coordination failure

Stream A is assigned to Codex above. It was taken by Claude anyway, on an
instruction to finish P4.0 rather than leave the phase open on an unstarted
stream. Codex had in fact started it and opened #59 with the same extraction;
#59 was closed as superseded, because #58 was already merged by the time it
appeared. No work was lost — #59 contained no function `main` lacks — but the
duplication was avoidable, and the mechanism that would have avoided it is the
one this document already specifies. An owner per stream is only worth writing
down if it is also honoured when the schedule presses.

### One decision the split settled differently than planned

Stream A above expects to swap `bevy::prelude::Vec3` for `glam::Vec3`, and
flags a Bevy bump introducing a second `glam` as a blocker to raise rather than
paper over. That hazard never arose. The DTOs carry positions as `[f32; 3]`;
every `Vec3` in the original module belonged to `ReplayState`, `RuntimeMarker`
and `MarkerKind`, which are playback and presentation rather than document
shape. Drawing the line there left them in the viewer, and left the new crate
needing no vector type at all.

#59 drew the line the other way — everything moved, `glam` as a direct
dependency, a `Deref` newtype in the viewer carrying the `Resource` derive.
That version makes a replay steppable without Bevy, which P4.8/P4.9 may want
when the Rust CLI reads replays. It was not carried over because that consumer
does not exist yet, and adding a version coupling for a speculative consumer is
what the retired B4 slice already cost this repo once. If it appears, #59 is
the design to return to — preferably with `RuntimeMarker.position` as
`[f32; 3]`, so the crate still needs no `glam`.
