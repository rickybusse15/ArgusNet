# Terrain semantics (P4.3c)

`src/argusnet/world/procedural.py` → `rust/argusnet-world/src/semantic.rs`.

Third slice of P4.3: the preset table, `np.quantile`/`np.median`, and
`_semantic_masks` — the pass where terrain stops being noise and becomes a
place. It carves rivers, fills lakes, floods a coast, flattens a compound pad,
then labels water, ridge, valley, steep-slope, lowland and road.

`tests/fixtures/semantic.json`, regenerated by
`scripts/capture_semantic_fixture.py`: 12 presets, 4 fallbacks, 80 quantiles,
8 medians and **52 runs** across seven scene configurations and both meshgrid layouts.

## It rewrites the height field while it runs

Four reads are **stale by design** — each uses a value computed before an edit
that came after — and reproducing that staleness is the whole job:

| Stale read | Used for | Obvious "cleanup" |
|---|---|---|
| `elev_norm`, from the **original** heights | `ridge_mask`, at the very end | recompute from the finished field |
| `slopes`, the **first** field | `lowland_mask` | reuse the post-smoothing field |
| `valley_mask`, a **snapshot** of `lowland_mask` | roads, river banks | alias the two |
| `_dilate_mask(water_mask, 0)` | nothing — zero iterations | delete it |

`elev_norm` is the sharpest: it is normalised from the heights as they arrive
and then read after rivers, lakes, coast, water levelling, smoothing and the
ground-plane floor have all edited the field. 44 of the 52 runs distinguish it
from a freshly recomputed one.

## `np.quantile` does not use one lerp

numpy switches interpolation form at the halfway point, to keep the result
monotonic in `q`:

```text
t <  0.5 : a + (b - a) * t
t >= 0.5 : b - (b - a) * (1 - t)
```

Using only the first branch disagrees on about **3%** of random inputs. This is
the *opposite* of `noise::value_noise` in P4.3a, where the plain
`a + t * (b - a)` form is the correct one. Two different functions in two
different libraries; they must not be unified.

## Mutation: 62 of 63 caught — after a first pass at 46

The first pass caught **46 of 63**, by far the weakest result in this
migration, and the cause was structural rather than a missing case here or
there.

**One scene configuration cannot exercise parameters that only matter at other
scales.** The fixture ran every preset, but all on one 14×13 grid at 25 m with
heights well above the ground plane. Twelve mutants survived simply because
that geometry could not reach them: the coastal 0.26/0.34 fractions landed
between the same two rows, the river amplitude difference was smaller than a
cell, no height sat within a metre of the ground plane, and the height span
never fell below the 1 m floor in the elevation normalisation.

The fix was seven scene configurations rather than more cases on one:

| Scene | Exists to reach |
|---|---|
| `base` | the preset branches on ordinary terrain |
| `low` | heights within 1 m of the ground plane, so water levelling and the ground floor are live |
| `flat` | a span under 1 m, so `max(h_max - h_min, 1.0)` stops being a no-op |
| `tiny_fine` | a scene scale under 4.35 m, so the river wavelength floor bites |
| `river_fine` | 64 rows, so the 0.035-vs-0.015 amplitude difference exceeds one cell |
| `fine_coast` | 40 rows, so 0.26 and 0.34 of the height fall on different rows |
| `exact_slope` | a slope landing **bit-exactly** on each steep-slope threshold |

Plus **profile overrides**, because the preset table cannot reach some
parameters at all: no preset has a `water_bias` above 0.35 or strictly between
0 and 0.01, so **both clamps in `min(max(water_bias, 0.01), 0.35)` are no-ops
on every real preset**. The port takes the profile as data, so the fixture
drives those directly.

Three of the closures are worth recording individually.

**A test of mine that asserted nothing.** All three `quantile` mutants survived
the first pass because the test only checked the results were *finite*. That is
not an assertion. The fixture now records 80 actual quantile values, and a
guard requires the cases to straddle numpy's `t = 0.5` switch — without cases
on both sides, either single-branch spelling passes.

**Two ratios that needed searching, not sampling.** The river wavelength floor
moves the centreline by millimetres on a coarse tiny scene — far under a cell —
so the geometry was searched for, then searched again for the *smallest* grid
that still discriminates, because the fixture is committed. Likewise the
amplitude difference is `0.02 × (n − 1)` cells regardless of resolution, so it
needs `n ≥ 60` on the axis the river is measured along; a 13-row grid cannot
see it at any scale.

**A threshold reached by construction.** `slope > t` versus `slope >= t` needs
a slope landing bit-exactly on 0.52 or 0.62. Two million random gradients
produced zero hits — but scanning ULPs around `tan(t)` found ramp steps that
land exactly there (20 cells at 0.52, 15 at 0.62). "Not found by sampling" is
not "unreachable", and the difference was worth two minutes.

### The one survivor is proven equivalent

`lake/level-applied-before-shore` swaps the shore clamp and the lake fill.
`dilate_mask(lakes, 1)` includes the lake cells themselves, so lakes are a
**subset** of the shore, and `min(lake_level, lake_level + 1.5)` is
`lake_level` — a lake cell ends at the same height either way. The reference's
order is kept anyway: the equivalence depends on the clearance being positive
and would break if it ever went negative.

## A real port bug, found by testing the layout production actually uses

`procedural_terrain_grid` builds its coordinate grids with numpy's **default**
meshgrid, so axis 0 is **y**. Every other caller — and the first version of
this fixture — uses `indexing="ij"`, where axis 0 is x. The two are transposes.

`_semantic_masks` is layout-agnostic for the **masks**, which come out as exact
transposes of each other. It is **not** layout-agnostic for the **heights**:
`_smooth_heights` sums its four neighbours in a fixed *positional* order,
transposition permutes that order, and floating-point addition is not
associative. The two layouts differ by up to **7.1e-15** on 5 of 63 cells —
nothing physically, everything to a fixture that compares bit patterns.

Adding `xy` runs failed immediately, and not by a ULP: `xy/lake_district` was
**0.013 m** off. The port was rebuilding 1-D axes from the 2-D grids —
`xx.at(i, 0)` — to call the axis-product `ellipse_mask`. Under the `xy` layout
that walks down a column of constant x, so the lake and compound-pad ellipses
landed in the wrong places.

The fix is `ellipse_mask_grid`, which evaluates **elementwise over the
coordinate grids**, exactly as `_ellipse_mask(xx, yy, ...)` does. The
axis-product form is kept as a convenience built on it, for callers that
genuinely hold separate axes. `grid_ops` gained two tests: one that the grid
form rejects mismatched shapes, and one that it gives transposed masks for the
same points in both conventions.

**The lesson is about coverage, not about ellipses.** A fixture can drive a
function correctly and still never exercise the way production calls it. The
guard now requires the `xy` runs to differ from their `ij` twins, so a future
change cannot quietly make them redundant.

## Fixture size

At 2.0 MB the first version violated the repo's own rule
(`PERFORMANCE_AND_BENCHMARKING.md` §5.5: large numeric artifacts do not belong
in the tree). Three changes brought it to **640 KB**, in line with the existing
`localization_steps.json`:

- `xx` and `yy` are **not stored** — they are exactly `i * resolution` and
  `j * resolution`. The capture script asserts that identity before omitting
  them, and the parity test rebuilds them.
- The largest scene was re-searched for the smallest grid that still
  discriminates: 24×48 → 30×12.
- Compact JSON separators, since a line per float more than doubled the file.

The layout runs added back ~70 KB, for a final **712 KB**.
